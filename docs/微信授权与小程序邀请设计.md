## 二、Web 端微信授权方案（存档）

### 2.1 选型：首选开放平台「网站应用」扫码登录

| 方案 | 适用场景 | 评价 |
|---|---|---|
| 开放平台网站应用（`snsapi_login`） | PC Web 扫码 | **首选**，体验标准、可控 |
| 认证服务号网页授权 | 微信内打开的 H5 | 备选；PC 端需"关注/扫码"变通，体验差 |
| 小程序码登录 | 有小程序后 | 可作为 Web 的补充登录方式（小程序扫码确认 → unionid 打通） |

### 2.2 登录/注册流程

```
Web 展示二维码（state 随机串写入 session/cookie，防 CSRF）
  → 用户扫码确认
  → 微信回调 /api/auth/wechat/callback?code=&state=
  → 校验 state
  → code + appid + secret → access_token + openid（+unionid）
  → 命中 unionid/openid：直接签发 JWT 登录
  → 未命中：进入「补充资料」页
        · 手机号（必填，唯一性校验 + 唯一索引兜底）
        · 用户名（必填，唯一）
        · 密码（选填，用于后续账号密码登录；不设则只能微信登录）
        · 师资身份（student 需上传学生证/身份证）
  → 创建用户（register_src=wechat）+ 签发 JWT
```

关键要求：
- **手机号唯一性**：与现行一致，应用层查重 + `idx_user_phone` 部分唯一索引兜底；
- `state` 一次性、短有效期，防 CSRF 与重放；
- `unionid` 优先于 `openid` 作为用户标识（便于 Web / 小程序 / 公众号多端打通）；
- 已有账号在登录态内可「绑定微信」，写入 openid/unionid，之后可用微信登录（**不做自动合并**，避免误绑）。

### 2.3 邀请码是否可以取消

**可以取消"强制"，但保留"能力"**：

| 结论 | 理由 |
|---|---|
| 取消强制邀请码 | unionid 是比短信更强的实名凭证（一个微信号 = 一个实名主体 + 手机号），批量成本远高于短信 |
| 保留邀请码表与管理员发码 | 微信接口故障、无微信用户、企业批量开通的降级兜底；`[invite] MODE` 开关一键切回 |
| 保留 `ref` 归因 | 推广归因与奖励结算需要 |
| 仍保留风控 | 微信号也能批量，仍需 IP/频率限制、unionid 唯一索引 |

### 2.4 试用期（已定）

- 微信授权注册：**先给 7 天**（`TRIAL_DAYS_WECHAT=7`）；
- 补足 30 天的激活条件（**推荐方案 B**，待确认）：**绑定手机号 + 创建第 1 个真实订单**；
- 补足方式：`member_expire += 23 天`，写一条 `recharge`（`source=self`、`amount=0`、`remark=微信激活补足`），不累加 `total_recharge`。

> 注意：不能用"完成微信授权"作为补足条件——微信授权在注册时已完成，否则等于注册即 30 天，收紧失去意义。

```go

// 唯一索引：uk_user_unionid ON "user"(wechat_union_id) WHERE wechat_union_id <> ''
```

## 三、小程序版邀请设计（存档）

### 3.1 登录方式差异

小程序：`wx.login()` → `code` → 后端 `code2session` → `openid/session_key/unionid`。
与 Web 本质区别：**小程序没有"账号密码登录"这个默认心智**，也拿不到微信绑定手机号（个人主体下 `getPhoneNumber` 不可用）。

### 3.2 邀请方式（小程序特有，远强于 Web）

| 方式 | 实现 | 说明 |
|---|---|---|
| 分享卡片 | `onShareAppMessage` → `path: /pages/register/index?ref=xxx` | 点对点分享，转化率最高 |
| 分享到朋友圈 | `onShareTimeline`（需基础库支持） | 场景值受限 |
| **带参小程序码** | `wxacode.getUnlimited`，`scene=refToken` | 可印制/长按识别，适合线下推广 |
| 复制链接 / 口令 | 兜底 | 用于无法扫码的场景 |

**关键约束**：`scene` 最大 32 个字符 → ref 必须用**短 token**（建议 8 位无歧义字符，去 `0/O/1/I/l`），不能用自增 ID 明文或 UUID。需在 `invite_code`（或新增 ref 表）维护 `token → inviter_id` 映射。

### 3.3 归因链路

```
分享（卡片 path?ref / 小程序码 scene=ref）
  → 小程序启动 onLaunch(options.query 或 options.scene)
  → 本地缓存 ref（可跨页面保留，注册页提交）
  → 注册接口带 ref → 写 invited_by_id + register_src=member_invite(+ platform=mp)
```

注意：小程序码进入时 `scene` 需 URL decode；从朋友圈/分享进入时场景值不同，需分别处理。

### 3.4 奖励与结算

**与 Web 完全共用后端**：`invite_reward` 表、`invited_by_id`、延时结算、连坐规则全部复用，仅 `platform` 字段区分来源。这样"Web 邀请到小程序注册"或反向也能正确归因与发奖。

## 四、小程序与 Web 的实现差异清单（重点）

| 维度 | Web（现行 / 计划） | 小程序（计划） | 影响 |
|---|---|---|---|
| 登录凭证 | JWT（手机号/邮箱 + 密码；后续加微信扫码） | `wx.login` code2session + 自定义登录态（建议同样签发 JWT，便于复用中间件） | 后端可复用 `middleware.AuthRequired`，只需新增登录入口 |
| 用户标识 | 用户名/手机号/邮箱 | `openid`，跨端用 `unionid` | `user` 需多端标识字段；**unionid 打通需绑定同一开放平台（待核实个人主体是否可行）** |
| 手机号 | 注册手填 + 唯一索引 | 个人主体下 `getPhoneNumber` 不可用 → 只能手填 | 手机号真实性保障弱于微信授权场景，需靠行为核验补 |
| 密码 | 注册必填 | 可无密码（微信即身份） | `password` 需允许为空；找回密码流程对无密码用户不适用 |
| 邀请凭证形态 | URL `?ref=` / 邀请码文本 | 分享卡片 path、小程序码 `scene`（32 字符上限） | 需要短 token 映射；**同一 ref 要能跨端解析** |
| 注册入口 | 弹窗 `AuthDialog` | 独立注册页（分享直达） | 前端不可复用，需重写 |
| 支付 | 线下扫码 + 管理员人工续费 | 小程序支付需企业主体+商户号，个人不可用 → **仍走线下人工续费** | 付费转化路径不变，`recharge.source` 仍为 `admin`；"首次付费"奖励触发点不变 |
| 消息触达 | 站内信 + 会员到期站内提醒 | 订阅消息（需用户授权，一次一授权） | 需新增「订阅消息」通道；到期提醒要引导用户订阅 |
| 风控信号 | IP、UA、频率 | 无稳定 IP（可拿客户端 IP）、可拿设备/微信风险等级 | 小程序端 IP 风控效果下降，更依赖 unionid 唯一 + 行为核验 |
| 审核与合规 | 无平台审核 | 小程序需类目与内容审核；个人主体可选类目受限（教育类需确认） | 上线前需确认类目可用性（待核实） |
| 前端复用 | Vue3 + Element Plus | 小程序原生 / uni-app / Taro | **视图层不可复用**；若要求复用，需引入 uni-app 或 Taro 重构，成本大 |
| 后端复用 | — | — | **可 100% 复用**：model / handler / 会员与奖励逻辑均不变，只新增认证方式与 `platform` 字段 |

## 五、落地顺序（资质具备后）

1. 取得开放平台网站应用 / 认证服务号资质 → 先做 **Web 微信扫码登录 + 绑定已有账号**（风险最低，可灰度）；
2. 开放微信授权注册（保留邀请码作为降级），试用期切到 7 天 + 激活补足；
3. 注册强制微信后，评估**取消邀请码强制**（保留能力 + 开关）；
4. 小程序版：`wx.login` 登录 + 分享/小程序码邀请，后端复用，前端独立；
5. 以 `unionid` 做三端统一账号，跨端邀请奖励互通。
