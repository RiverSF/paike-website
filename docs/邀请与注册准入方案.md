| 事实 | 位置 |

## 二、Web 端会员邀请方案（**方案存档 · Web 端暂不实施，已移至小程序功能手册**）

> 以下 2.1 ~ 2.6 为设计存档，规则直接沿用到小程序端（见 `docs/小程序功能手册.md` 的 F2）。
> Web 端当前不提供任何会员自助分享入口，`[invite] MODE` 保持 `manual`。

### 2.1 三层解耦模型

```
渠道归因层  ref 链接（可复用、无状态）→ 记录 invited_by_id / register_src
准入凭证层  管理员邀请码（人工、绑手机号）｜会员邀请链接（自助、不绑手机号）  ← 二者并存
信用结算层  配额 + 延时结算 + 连坐 → 控制"有效性"与奖励发放
```

### 2.2 谁能发邀请链接

| 会员状态 | 是否可生成邀请链接 | 月配额 |
|---|---|---|
| 试用会员（trial） | **否** | — |
| 付费会员（monthly/quarterly/yearly/permanent，未过期） | 是 | 3（可动态调整） |
| 已过期 / 被冻结 / 有违规记录 | 否 | — |

配额动态调整：连续有效邀请 +1；出现垃圾号 -1；连续 2 例无效 → 暂停发链接权。

### 2.3 注册链路（与被邀请人视角）

1. 分享人在个人中心点「邀请有礼」→ 复制链接 `https://<域名>/register?ref=<token>`
2. 被邀请人打开链接 → 前端 `AuthDialog` 自动填充 ref（只读，不可改），顶部提示"由 XXX 邀请"
3. 后端 `GET /api/invite/resolve?ref=xxx`（公开）校验有效性并回显邀请人昵称
4. 注册时**免邀请码**（ref 即准入凭证），仍需：用户名、密码、手机号（唯一性校验）、师资身份
5. 注册成功 → 写入 `invited_by_id`、`register_src=member_invite`、`register_ip`
6. 注册即成为免费会员（试用）→ **分享人 +7 天**
7. 被邀请人首次付费（管理员录入续费）→ **分享人再 +15 天**

### 2.4 奖励规则

| 触发事件 | 奖励 | 到账时点 | 备注 |
|---|---|---|---|
| 被邀请人注册成功（成为免费会员） | 分享人 +7 天 | **T+7 天延时**，且被邀请人账号正常（未冻结） | 防注册即弃号 |
| 被邀请人首次付费（产生 `recharge`） | 分享人 +15 天 | 付费录入成功后 | 每个被邀请人只计一次 |
| 被邀请人被判定为垃圾号/冻结 | 回收已发奖励 | 立即 | 连坐 |

实现要点：
- 加天数统一走 `member_expire = max(member_expire, now) + days`，并写一条 `recharge` 流水（`source=self`、`amount=0`、`remark=邀请奖励`），**不得累加 `total_recharge`**；
- 奖励记录独立表 `invite_reward(inviter_id, invitee_id, stage, days, status, qualified_at, granted_at, revoked_reason)`，`status: pending → qualified → granted / revoked`；
- 单人累计奖励上限（建议每年不超过 90 天），防薅。

### 2.5 有效性保障（无短信前提下的核心）

| 手段 | 做法 |
|---|---|
| 延时结算 | 注册 ≠ 奖励到账；T+7 天仍活跃且未被冻结才计入有效邀请 |
| 连坐 | 被邀请人被冻结/判垃圾 → 扣配额、回收奖励，连续 2 例暂停发链接权 |
| 配额 | 每月 3 个；链接 7 天未注册自动失效回收 |
| 轻量风控 | 同 IP 24h 注册上限 3、同 `/24` 网段上限、注册失败 5 次弹滑块/图形验证码 |
| 兜底 | 管理端可按 `register_src` 筛选"会员邀请来源"账号做抽样人工复核 |

### 2.6 降级开关

`server/internal/conf/app.ini`：

```ini
[invite]
MODE = manual   # manual=仅管理员发码（当前）member=开放会员邀请链接
```

出现刷号时改回 `manual` 重启即全站降级，无需改代码。
