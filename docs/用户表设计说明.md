# 用户表设计：字段分组与「是否拆分」评估

> 结论先行：**当前阶段不拆分 `user` 表**，只做字段分组与文案统一。理由见下方评估。

## 一、字段分组（`server/internal/model/user.go`）

| 分组 | 字段 | 说明 |
| --- | --- | --- |
| A. 账号信息 | `id` `username` `password` `avatar` `phone` `email` `phone_changed_at` | 登录凭据与联系方式，注册后基本不变 |
| B. 角色与状态 | `role` `status` | `owner=站长` / `admin=管理员` / `user=普通用户`；`normal` / `frozen` |
| C. 师资身份 | `user_role` `teacher_type` `reg_teacher_type` `verified` `student_*` | 仅普通用户有意义，决定会员价格档位 |
| D. 会员信息 | `member_type` `member_start` `member_expire` `member_expire_notified` `total_recharge` | 展示口径三类：免费试用 / 付费会员 / 永久会员 |
| E. 注册归因与风控 | `invited_by_id` `register_ip` `register_src` `created_at` `updated_at` | 推荐归因、同 IP 聚集风控 |

## 二、为什么不把「会员信息」拆成 `user_member` 表

评估维度：

1. **基数**：会员与账号是 1:1，且几乎每个账号都有会员行，拆表无法减少行数。
2. **读取模式**：用户列表、总览统计、课表与下单前的会员校验，**每次**都要读会员类型与到期时间；拆表后这些查询必须 `LEFT JOIN`，并引入「用户存在但会员行缺失」的第三种状态。
3. **写入模式**：续费 / 开通 / 学生身份转化都要在**同一事务**里同时判断与更新账号 + 会员。合表时是一次 `UPDATE`；拆表后任何漏改都会造成「显示已开通但订单被拒」这类不一致。
4. **索引**：现有 `idx_user_member_expire (member_expire)` 已覆盖「按到期时间筛选 / 排序」；拆表后同样的查询要改成跨表 JOIN，索引收益不变，成本上升。
5. **真正需要拆分的是高频增长数据**：站内信 `message`、订单 `order`、课次 `lesson`、充值 `recharge`、反馈 `feedback` —— 这些已独立成表，符合「增长数据外置」原则。

因此：**保持单表**，用分组注释 + 统一文案保证可维护性；会员到期提醒标记（`member_expire_notified`、`student_expire_notified`）是派生状态，留在主表最省事。

## 三、何时应该重新评估

出现下列情况时再拆表，届时按「1:1 且高频写入」优先拆：

- 会员字段继续膨胀（如加入优惠券、积分、企业账户、合同到期），单行宽度影响明显；
- 会员信息需要独立的历史版本 / 审计（多版本有效期追溯）；
- 会员数据需要独立权限边界或独立缓存（热点集中在会员而非账号）。

拆分时的实施要点：
- 新表 `user_member (user_id PK, member_type, member_start, member_expire, total_recharge, updated_at)`；
- 迁移脚本用 `INSERT ... SELECT` 从 `user` 回填，一次性完成、无需停机；
- 所有续费 / 开通逻辑改为事务内同时写两表；
- 读路径统一走 JOIN 或仓储层封装，禁止散落 SQL。

## 四、统一文案口径

| 概念 | 取值 | 展示文案 |
| --- | --- | --- |
| 角色 `role` | `owner` / `admin` / `user` | 站长 / 管理员 / 普通用户 |
| 身份（staff） | `owner` / `admin` | 超级管理员 / 运营管理员 |
| 身份（普通用户） | `student` / `professional` | 大学生家教 / 专职老师 |
| 会员类型（展示） | `trial` / `paid`（daily、monthly、quarterly、yearly） / `permanent` | 免费试用 / 付费会员 / 永久会员 |

后端对应实现：`model.RoleName`、`model.StaffIdentityName`、`model.TeacherTypeName`、`model.MemberTypeName` 与 `model.MemberTypeGroup`。
