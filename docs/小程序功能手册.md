## 一、能力前提与限制（决定哪些功能能做）

| 能力 | 个人主体 | 说明 |
|---|---|---|
| `wx.login` 获取 openid | 可用 | 小程序登录基础能力 |
| unionid（跨端打通） | **待核实** | 通常需将小程序绑定到微信开放平台；开放平台认证与企业资质要求需复核 |
| `getPhoneNumber` 获取微信绑定手机号 | **不可用（待核实）** | 需企业主体且按次付费 → 手机号只能用户手填 |
| 微信支付 | 不可用 | 需企业主体 + 商户号 |
| 订阅消息 | 可用 | 一次授权一次推送，需在前端引导订阅 |
| 分享到好友 / 群 | 可用 | `onShareAppMessage` |
| 分享到朋友圈 | 受限可用 | `onShareTimeline`，依赖基础库与平台策略 |
| 带参小程序码 `wxacode.getUnlimited` | 可用 | `scene` 上限 **32 字符** |
| 客服会话（`button open-type=contact`） | 可用 | 可替代 Web 端"扫码加微信"的人工链路 |
| 小程序类目审核 | 需确认 | 教育类目对个人主体是否开放**待核实** |

> 落地前必须以微信官方最新规则复核上表「待核实」项。

## 三、F1 · 微信授权登录与注册

### 3.1 登录

```
小程序 wx.login() → code
  → 后端 code2session（appid + secret + code）→ openid / session_key / unionid
  → 命中 openid/unionid → 签发 JWT（与 Web 同一套中间件）
  → 未命中 → 进入注册（补资料）
```

- 登录态**沿用 Web 的 JWT**（新增登录入口，不改 `middleware.AuthRequired`）；
- `unionid` 优先作为跨端统一标识，`openid` 兜底；
- 存量 Web 账号：在 Web 端登录态内「绑定微信」写入 `wechat_union_id`，之后可用小程序登录；**不做自动合并**，避免误绑。

### 3.2 注册（授权后补资料）

授权成功只拿到微信身份，**业务信息仍需补填**：

| 字段 | 必填 | 校验 |
|---|---|---|
| 手机号 | 是 | 格式 `^1[3-9]\d{9}$` + **唯一性**（应用层查重 + `idx_user_phone` 部分唯一索引兜底） |
| 用户名 | 是 | 唯一、不含空白 |
| 密码 | 否 | 小程序端可无密码；设置后可用于 Web 账号密码登录 |
| 师资身份 | 是 | `student` 需上传学生证 + 身份证，进入 `student_application` 审核队列 |
| ref（邀请） | 否 | 来自分享卡片/小程序码，见第四节 |

注册落库：`register_src = wechat`、`register_ip`、`invited_by_id`（有 ref 时）。

### 3.3 数据模型新增

```go
// user 新增（Web 端届时同步加，用于绑定）
WechatOpenID   string // 小程序 openid
WechatUnionID  string // 跨端统一标识
WechatNickname string
WechatAvatar   string
Platform       string // 注册端：web / mp
// 索引：uk_user_unionid ON "user"(wechat_union_id) WHERE wechat_union_id <> ''
//      uk_user_mp_openid ON "user"(wechat_open_id)  WHERE wechat_open_id <> ''
```

## 四、F2 · 会员邀请与分享（核心）

### 4.1 目标

让付费会员在微信生态内低成本分享（好友/群/朋友圈/小程序码），系统准确归因并在有效转化后奖励会员天数。

### 4.2 三层模型

```
渠道归因层  ref 短 token（可复用、无状态）→ inviter_id + register 来源标记
准入凭证层  小程序端：微信授权（`wx.login` 身份）本身即凭证，无需额外准入码
信用结算层  配额 + 延时结算 + 连坐 → 保证"通过分享注册的是有效会员"
```

> 与 Web 的关键差异：Web 为手机号自助注册（无微信授权），只能靠手机号唯一性 + 行为风控做准入；**小程序端微信身份本身就是强准入凭证**，所以邀请退化为纯"归因 + 激励"，不再承担防刷职责——这也是把分享功能放到小程序做的主要原因。

### 4.3 分享形态与归因

| 形态 | 实现 | 备注 |
|---|---|---|
| 分享卡片（好友/群） | `onShareAppMessage` → `path: /pages/register/index?ref=<token>` | 主路径，转化最高 |
| 带参小程序码 | `wxacode.getUnlimited`，`scene=<token>` | 可保存/印制/长按识别，适合线下；**scene ≤ 32 字符** |
| 分享到朋友圈 | `onShareTimeline` | 依赖平台策略 |
| 复制链接 / 口令 | 兜底 | 无法扫码场景 |

**ref 短 token 规则**：8 位，字符集去易混淆字符（`0/O/1/I/l`），不含特殊符号，大小写不敏感；在**独立 `invite_ref` 表**维护 `token → inviter_id` 映射（Web 端原 `invite_code` 表已删除，不可复用）。

**归因链路**：
```
小程序 onLaunch / onShow：
  options.query.ref（扫码/分享卡片）或 options.scene（小程序码，需 decode）
  → 本地缓存 ref（跨页面保留，直到注册成功或超时）
  → 注册接口提交 ref → 校验 → 写 invited_by_id / register_src / platform
```

### 4.4 谁能发邀请（配额）

| 会员状态 | 可否分享 | 月配额 |
|---|---|---|
| 试用会员 trial | 否 | — |
| 付费会员（未过期） | 是 | 3（可动态调整） |
| 已过期 / 冻结 / 有违规 | 否 | — |

动态调整：连续有效邀请 +1；出现垃圾号 -1；连续 2 例无效 → 暂停分享权限。

### 4.5 奖励规则（已确认）

| 触发事件 | 奖励 | 到账时点 |
|---|---|---|
| 被邀请人注册成功（成为免费会员） | 分享人 **+7 天** | **T+7 天延时**，且被邀请人账号正常（未冻结、未判垃圾） |
| 被邀请人**首次付费**（管理员录入 `recharge`） | 分享人 **再 +15 天** | 付费成功后，每个被邀请人只计一次 |
| 被邀请人被冻结/判垃圾 | **回收**已发奖励 | 立即（连坐） |

实现要点：
- 加天数统一 `member_expire = max(member_expire, now) + days`，写一条 `recharge`（`source=self`、`amount=0`、`remark=邀请奖励`），**不累加 `total_recharge`**；
- 独立表 `invite_reward(inviter_id, invitee_id, stage, days, status, qualified_at, granted_at, revoked_reason)`，`status: pending → qualified → granted / revoked`；
- 单人每年奖励上限（建议 90 天）。

### 4.6 试用期与激活补足（D6）

- 非人工来源注册（含微信授权 + 分享注册）：**先给 7 天**；
- 补足到 30 天的激活条件（推荐）：**绑定手机号 + 创建第 1 个真实订单**；
  - 备选 A：仅绑手机号即补足（最宽松）；
  - 备选 C：绑手机号 + 管理员人工复核（最严）；
- 补足实现：`member_expire += 23 天`，写 `recharge(source=self, amount=0, remark=激活补足)`；
- 试用期天数在 `server/internal/conf/app.ini` 里以独立配置项提供（原 `[invite] TRIAL_DAYS_*` 已随邀请码下线移除）。

> 不能用"完成微信授权"作为补足条件：授权在注册时已完成，否则等于注册即 30 天，收紧失去意义。

### 4.7 有效性保障（无短信/无手机号核验的前提）

| 手段 | 做法 |
|---|---|
| 微信身份 | openid/unionid 唯一索引，一个微信号只能占一个账号（**这是小程序端相对 Web 的最大优势**） |
| 延时结算 | 注册 ≠ 奖励到账，T+7 天仍正常才计入 |
| 连坐 | 被邀请人被冻结/判垃圾 → 扣配额、回收奖励 |
| 配额 | 月 3 个；链接/码 7 天未注册自动失效 |
| 轻量风控 | 同 IP 24h 注册上限、注册失败多次弹图形验证码、异常聚集告警 |
| 兜底 | 管理端可按 `register_src` 筛选"分享来源"账号抽样复核 |

### 4.8 降级开关

`server/internal/conf/app.ini`：

```ini
[invite]
MODE = manual              # manual=仅管理员发码；member=开放会员分享（小程序端启用时切换）
MEMBER_MONTHLY_QUOTA    = 3
MEMBER_CODE_EXPIRE_DAYS = 7
WECHAT_LOGIN_ENABLED    = false
TRIAL_DAYS_INVITE       = 30
TRIAL_DAYS_WECHAT       = 7
```

出现刷号时 `MODE` 改回 `manual` 重启即全站降级。

### 4.9 接口清单（后端，与 Web 共用）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/invite/mine` | 登录 + 付费会员 | 我的邀请链接/小程序码、剩余配额、邀请列表与奖励状态 |
| POST | `/api/invite/generate` | 登录 + 付费会员 | 生成邀请凭证（受配额与日限） |
| GET | `/api/invite/qrcode` | 登录 + 付费会员 | 返回带 `scene` 的小程序码 |
| GET | `/api/invite/resolve?ref=` | 公开 | 解析 ref，回显邀请人昵称与是否有效 |
| POST | `/api/auth/wechat/login` | 公开 | code2session → 登录/引导注册（F1） |
| POST | `/api/user/register` | 公开 | 支持 `ref`（归因用）；入参：用户名、密码、手机号 |
| GET | `/api/admin/invite/stats` | 管理员 | 按邀请人聚合：邀请数、有效率、垃圾率、付费转化 |
| POST | `/api/admin/invite/:id/revoke` | 管理员 | 撤销邀请凭证 |
| POST | `/api/admin/rewards/:id/grant\|revoke` | 管理员 | 奖励人工发放/回收 |

### 4.10 前端（小程序）页面与埋点

| 页面 | 内容 |
|---|---|
| 我的 → 邀请有礼 | 我的邀请链接/小程序码、一键分享、剩余配额、邀请进度（已注册/已达标/已失效）、已获奖励天数 |
| 注册页 | 顶部"由 XXX 邀请"提示；手机号、用户名、师资身份；ref 自动带入不可改 |
| 埋点 | 分享曝光/点击、链接打开、注册开始/完成、激活补足完成、首次付费 |

### 4.11 分期

| 期 | 内容 | 风险 |
|---|---|---|
| M0 | `wx.login` 登录 + 注册补资料 + unionid/openid 索引 | 中（依赖资质核实） |
| M1 | 只读 `ref` 归因 + 管理端统计（不发码、不发奖励） | 低 |
| M2 | 付费会员配额分享 + 免码注册 + 试用期 7 天 + 激活补足 | 中 |
| M3 | 奖励结算（7/15 天）+ 延时结算 + 连坐 + 风控看板 | 中 |
